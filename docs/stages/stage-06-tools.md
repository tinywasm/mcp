# Stage 6 — tools.go + provider.go

## 6.1 — Rename and simplify public types

```go
// Before
type CallToolRequest  → type Request
type CallToolResult   → type Result
type ToolHandlerFunc  → (inlined as func field in Tool)
type ToolFilterFunc   → type FilterFunc
```

## 6.2 — Request.Bind: SafeFields boundary

Tool arguments come from an external client — decode and validate at the boundary.

```go
// Before
func (r *CallToolRequest) BindArguments(target any) error

// After
func (r *Request) Bind(target fmt.SafeFields) error {
    if err := json.Decode(r.Params.Arguments, target); err != nil {
        return err
    }
    return target.Validate('c')
}
```

`r.Params.Arguments` is a `string` containing the raw JSON object of arguments.

Tool providers define their argument structs **without** `// ormc:formonly`
so that `ormc` generates `Validate()`. Example (in tool provider code, not in mcp):

```go
type SearchArgs struct {
    Query string `validate:"required,min=1,max=255,letters,spaces"`
    Limit int64  `validate:"min=1,max=100"`
}
// ormc generates Schema(), Pointers(), Validate() → implements fmt.SafeFields
```

## 6.3 — Tool: single type with Run handler included

`ProtocolTool` and `Tool` (provider.go) merge into one type.
The handler (`Run`) lives inside `Tool` — no separate registration:

```go
type Tool struct {
    Name        string
    Description string
    InputSchema string // JSON schema string, generated by ormc
    Resource    string // required — RBAC resource identifier
    Action      byte   // required — 'c','r','u','d'
    Run         func(ctx *context.Context, req Request) (*Result, error)
}
```

`Resource` and `Action` are always required. `AddTool` returns an error if either is empty.
`Run` is required. `AddTool` returns an error if nil.

Registration is one call, one object:

```go
srv.AddTool(mcp.Tool{
    Name:        "search",
    Description: "Search items",
    InputSchema: new(SearchArgs).Schema(),
    Resource:    "items",
    Action:      'r',
    Run: func(ctx *context.Context, req mcp.Request) (*mcp.Result, error) {
        var args SearchArgs
        if err := req.Bind(&args); err != nil {
            return nil, err // server wraps as JSON-RPC error
        }
        return mcp.Text("results"), nil
    },
})
```

## 6.4 — Short constructors for Result

```go
// Before
func NewToolResultText(text string) *CallToolResult
func NewToolResultJSON(data fmt.Fielder) (*CallToolResult, error)
func NewToolResultError(err error) *CallToolResult

// After
func Text(text string) *Result
func JSON(data fmt.Fielder) (*Result, error)
```

`NewToolResultError` is deleted — handlers return `nil, err` and the server
converts the error to `{"isError": true, "content": ...}` automatically.

`Text` implementation:
```go
func Text(text string) *Result {
    c := &textContent{Type: "text", Text: text}
    var s string
    _ = json.Encode(c, &s)
    return &Result{Content: s}
}
```

## 6.6 — Delete from provider.go

- `Parameter` struct — schema is now a pre-built string (generated by ormc)
- `ToolExecutor func(args map[string]any)` — replaced by `Tool.Run`
- `Tool.Execute` field — replaced by `Tool.Run`
- `BinaryData` struct — move to `handler_executor.back.go` (server-only)

## 6.7 — Delete from tools.go

- `GetArguments() map[string]any`
- `GetRawArguments() any`
- `GetString()`, `GetInt()`, `GetBool()` — callers use `Bind()` with typed structs
- `ProtocolTool` type + `NewProtocolTool` constructor
- `ToolArgumentsSchema`, `ToolInputSchema`, `ToolOutputSchema` — replaced by `InputSchema string`
- `ToolListChangedNotification` type — use `Notification` with method constant
- Custom `MarshalJSON`/`UnmarshalJSON` on `CallToolResult`/`ProtocolTool`

## 6.8 — Delete tool_builders.go entirely

The entire builder DSL (`ToolOption`, `PropertyOption`, `WithDescription`,
`WithString`, `WithNumber`, `WithBoolean`, `Required`, `Description`, `Enum`,
`DefaultString`, `DefaultNumber`) is obsolete — schemas are generated by ormc.

## 6.9 — Error auto-wrapping in server

When `Tool.Run` returns `(nil, err)`, the server catches it and produces:

```go
func handleToolError(err error) *Result {
    return &Result{
        Content: Text(err.Error()).Content,
        IsError: true,
    }
}
```

Callers never need to construct error results manually.

## 6.10 — Remove imports

Delete: `"encoding/json"`, `"reflect"`, `"errors"`, `"fmt"`, `"strconv"`, `"net/http"` (stdlib)
Use `github.com/tinywasm/fmt` for errors: `fmt.Err("mcp", "tools", "message")`
